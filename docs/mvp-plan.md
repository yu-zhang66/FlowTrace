# FlowTrace MVP 计划

## 目标

以 `supply_chain` 的融资申请审批流程完成“采集旧流程 → AI 生成案例 → 新旧双跑 → 自动比较 → 报告和发布门禁”的闭环。由于新流程尚未开发，首期使用旧流程适配器作为 current adapter 的临时替身，先验证工具链；后续只替换配置和适配器即可切换到真实新流程。

## MVP 能力

1. 采集流程节点、规则、角色、状态、页面、业务 API、关键数据和外部调用，并生成 Markdown 人工审核稿。
2. 使用统一业务动作：`SUBMIT`、`APPROVE`、`REJECT`、`RETURN`、`WITHDRAW`、`TRANSFER`、`COUNTERSIGN`。
3. 生成并校验 YAML/JSON 测试案例，保留证据引用。
4. 通过适配器执行旧流程和新流程，允许引擎 API 完全不同。
5. 比较最终状态、语义路径、角色、关键数据库字段和外部调用。
6. 执行页面关键路径：登录、填写、提交、审批、退回和查看结果。
7. 输出 HTML/Markdown/JSON 报告，P0 阻断发布，P1 需要确认。
8. 第一阶段提供 `FlowTrace Skill`，编排采集、案例生成、校验、执行和报告。
9. 第一阶段提供轻量测试管理和报告页面；页面设计和体验优化使用 `ui-ux-pro-max` skill。
10. MVP 使用 Git 管理文件化产物，不依赖 FlowTrace 自身数据库。
11. JSON/YAML 作为机器源文件，Markdown 由程序自动渲染，提供给人审核和阅读。
12. 将核心引擎与项目配置、适配器、案例和 fixtures 分离。

## 不在 MVP 范围

- 完整流程设计器
- 自动修改核心业务代码
- 生产环境自动切流
- 全量历史流程迁移
- 一开始覆盖全部供应链流程

## 阶段

1. 核心模型与适配器 SDK。
2. 融资申请审批旧流程基线采集。
3. 案例 Schema 和 AI 生成/校验。
4. 使用旧流程替身完成旧新双跑、结果比较和差异分级。
5. 数据库隔离、外部系统 Mock 和 API/流程关键路径。
6. 轻量前端页面、HTML/Markdown 报告和 CI 门禁。
7. 新流程开发完成后，替换 current adapter 并执行真实迁移验证。
